The problem

Your customer truth lives in the BSS. Your marketing tools make you ship it out and wait.

The standard stack dumps BSS data into a marketing app or warehouse, builds an audience there, and syncs it back for activation. Every segment is a round-trip across vendor boundaries — measured in hours, not seconds — before anything reaches a customer or a model can learn.

The round-trip

Dump → build → sync back

  • BSS → warehouse/marketing tool → audience → reverse-ETL → activation
  • Batch latency on every refresh; the AI feedback loop is split across vendors
  • A second copy of the customer to secure, govern and reconcile
BSS-native

The event bus is the feed

  • Orders, party, usage, billing → customer traits, as they happen
  • Audiences resolve in-house; owned-channel activation is instant
  • The BSS is already the store, the identity, the channels and the AI

What's inside

The add-on

Already run a BSS? The module runs on top of it — through one adapter.

The martech services depend on a tiny event envelope, not on this BSS. A thin, config-driven bridge normalizes a foreign BSS's own events onto the ingress topic. Onboarding a new BSS is a mapping config and a deploy — never a code fork.
