## B. Agent-era surfaces — where the effort is better spent

In order. None of these is started.

1. **`ui://` resources on the ontology's MCP server → desks as MCP Apps.**
   The expensive half exists: governed actions over `tools/list`/`tools/call`
   with an approval ladder and receipts. `resources/list` returns an empty
   list, so there is no UI surface. An MCP App is a self-contained HTML page
   rendered in a sandboxed iframe with a declared CSP, framework-agnostic
   (official templates include vanilla JS). Build the app as its own small
   bundle — do not ship the console's React tree into a sandbox.
2. **An A2A surface.** The genuine gap of the three: no agent card, no task
   endpoint. A2A is v1.0 under the Agentic AI Foundation and explicitly
   excludes user interfaces, so this is purely about what the BSS exposes —
   another operator's agent transacting with this one under the same
   governance as the ontology's registered actions.
3. **Agentic commerce conformance.** Already planned in detail in
   [agentic-commerce-plan.md](agentic-commerce-plan.md) (ACP: product feed,
   `checkout_sessions` lifecycle, delegated payment token). The per-tenant
   gates exist (`agent-commerce: off|discovery|full`, `ai-visibility`).
   **Action: establish what of that plan is built before planning more.**

## C. Security — knowingly left open

Closed items are in the commit history from 23 September; these are the
remainders, with the reason each was not closed.

| Item | Why it is open |
|---|---|
| **`numberOffer` enumeration oracle** | Rate-limited to 30/min per caller (a third ring at the gateway), which slows a walker but does not close it. Absence still means assigned. A real fix needs the endpoint to stop answering "is this number free" anonymously, which conflicts with a shopper picking a number before sign-in. |
| **DNS rebinding on `CallbackUrlPolicy`** | The host is resolved by the policy and again by the HTTP client. Closing it means checking at connection time, which the JDK client does not expose cheaply. The allow-list carries the weight. |
| ~~**`taranga` still has `ai-raw-exposure: true`**~~ | **Closed 24 Sep (PR #27).** Now `${AI_RAW_EXPOSURE_TARANGA:false}` like every other tenant, and `ops/arch/claims.sh` refuses a literal `true` anywhere in `tenants.yml`. Labelled personal names are redacted too, and the AI ledger has retention on two clocks. |
| **Existing realms share the template's machine secrets** | Onboarding now mints per-tenant secrets; serving realms were not rotated because that restarts trust across ~20 running components. Operator steps in `docs/tenant-onboarding-secrets.md`. |
| **`fjord` realm and registry are out of step** | Its realm has a generated secret; the committed `tenants.yml` has the old template reference. Fixed by re-running `third_operator_test.js`, which re-onboards it. Inherent to onboarding writing a generated default into a git-tracked file. |
| **39 `SecurityConfig` copies have no drift check** | Every component validates tokens itself; nothing proves they agree. Wants a conformance step in `ontology_test.js` (#125 already walks routes): every component rejects a token from a realm not in `tenants.yml`. |
| **An AI audit write failure does not fail the call** | `AiGovernor.record` catches and warns; the model call still returns. Money-grade would be: no receipt, no act. Also, ontology receipts are dropped with a warn when Kafka is down — they should ride the outbox. |
| **No `seam_gap` ledger** | Every fail-soft seam logs a warning; warnings are not a ledger and the console shows nothing. Wants an outbox event per fail-soft, surfaced on the Operations page. |
| **No body-size cap at the gateway** | `spring.codec.max-in-memory-size` unset; no request-body limit at the edge. |
| **`docs/threat-model/` is not published** | Ten STRIDE documents, local only (`.git/info/exclude`). Publish once the deployment concerns below are addressed — several name live weaknesses of the hosted box. |

### Hosted box — deployment concerns, untouched on purpose

Nothing here was changed; the box is not modified without being asked.

- **The Caddy basic-auth gate is bypassed by any request carrying
  `Authorization: Bearer*`** — the matcher exempts it. The app's own login
  still applies, but console HTML, JS and every public route are served.
  Rated high in the threat model.
- **87 host ports on `0.0.0.0`**; the security group is not code and cannot be
  diffed. Four PSP mocks are intentionally public and accept any payment.
- **SSH without MFA**, single-user box, no separation between deploy and
  operate.
- **No image provenance** — a tampered local build is indistinguishable from
  a clean one. (Same gap as review item TAR-10/18: SBOM, signing, digests.)
